# Proton documentation

Uses mdBook 0.4.52 with its default theme. Install the `mdbook` binary; no
MoonBit, Node.js, npm or build plugins are required.

## Write

Edit Markdown in `content/en/` and `content/zh/`. Keep both translations and
code examples aligned. Add chapters to each language's `SUMMARY.md` and use
`.md` links between articles. Do not add per-page language-switch links.

The book has six top-level chapters in both languages: Introduction, Tutorial,
Command Line Interface, Configuration, Examples, and Release Notes. Keep all
CLI commands and options in `command-line-interface/commands.md`, and all project JSON fields in
`configuration/project.md`. Examples contains ten curated source references pinned to
the documented release commit; release notes distinguish publication from
source changes.

Each language directory follows the book navigation:

```text
SUMMARY.md
introduction/
tutorial/
command-line-interface/
configuration/
examples/
release-notes/
```

Use descriptive filenames for content pages. All six top-level chapters are
navigation groups without landing pages; content belongs in their child pages. Preserve old published URLs with
redirects in both book configs.

Tutorials live only in `content/<language>/tutorial/` and the Tutorial navigation
section. They state prerequisites, file edits and expected results. All other
pages are independently readable technical documentation: define concepts, API
contracts, configuration types/defaults, lifecycle, failure behavior and platform
limits. Do not make reference pages depend on completing a tutorial project.
Examples document Proton 0.3.4; verify them with published dependencies.

## Preview

From `website/`, build both languages under the deployment path and serve them:

```sh
preview_dir="$(mktemp -d)"
mdbook build --dest-dir "$preview_dir/proton"
mdbook build zh --dest-dir "$preview_dir/proton/zh"
python3 -m http.server 4173 --bind 127.0.0.1 --directory "$preview_dir"
```

Open http://127.0.0.1:4173/proton/ for English or
http://127.0.0.1:4173/proton/zh/ for Chinese. This optional local preview uses
Python 3; document builds still require only mdBook. Rebuild both languages
with the same destination paths after editing.

The first content page is `introduction/architecture.md`. The generated site
homepage redirects there, keeping relative Markdown links correct without a
separate homepage source or hardcoded HTML links in the content.

## Publish

```sh
mdbook build
mdbook build zh
```

The `documentation` workflow runs these commands and deploys `dist/` to GitHub
Pages on `main`. Select **GitHub Actions** as the repository's Pages source.
The site URL is https://moonbit-community.github.io/proton/.

Default theme assets are generated by mdBook and are not committed.
The shared `theme/highlight.js` adds the existing MoonBit language definition
to Highlight.js 11.11.1. See [theme/README.md](theme/README.md) for provenance. Update the
release title in both `book.toml` files when updating the documented release.

## Content validation

`python3 scripts/check_book.py` (from the repository root) checks bilingual page
and code-block parity, navigation coverage, local page links, the declared
Proton version, and the pinned release commit. Example excerpts must match that commit. After
building both books, add `--html` to validate generated links and anchors. Historical release notes keep
their original versions. A new release requires updating the book titles,
installation/dependency examples, API links, pinned example source commit and
release notes together; do not replace Warren's independent version.

For executable validation, install the documented registry CLI and run:

```sh
python3 scripts/check_book.py --cli "$HOME/.moon/bin/proton_cli" --tutorials
```

This extracts code directly from the Markdown, assembles the minimal tutorials
(including the incremental event/window changes) and modified Todo template in
an independent temporary directory, checks both compilation targets, runs the
Todo tests, decodes the complete configuration examples with the published
parser, and checks CLI help options against the reference. Failed projects are
retained for diagnosis. It does not open windows or claim GUI/package acceptance.

The documentation workflow runs these checks on pull requests and main changes,
including code-only changes, and requires them before deployment. Building the
book itself still needs only mdBook; Python and MoonBit are validation tools,
not website build dependencies. Before changing a tutorial's visible behavior,
also run its stated manual acceptance on the affected platform. Cross-platform
packaging remains covered by the release registry smoke workflow; a passing
Markdown build is never proof that an application runs.
